# 开源乓协 V1.0 文档目录

本目录是开源乓协 V1.0 的产品与工程开发基线，供开发人员及 Codex 使用。

## 阅读顺序

1. `PRODUCT_SPEC_V1.md`：系统做什么、业务边界是什么。
2. `IMPLEMENTATION_SPEC.md`：Codex 应如何分阶段实现。
3. `DATABASE.md`：核心数据库实体、约束与一致性要求。
4. `API.md`：V1 API 契约和错误码约定。
5. `PERMISSIONS.md`：身份、职务与权限矩阵。
6. `COMPETITION_RULES.md`：比赛状态机、单淘汰、小组循环、比分与晋级。
7. `RATING_RULE.md`：1400 初始积分及逐场积分算法。
8. `UI_PAGES.md`：页面与导航清单。
9. `TEST_PLAN.md`：单元、集成、并发和性能验收。
10. `NON_OFFICIAL_NOTICE.md`：非官方性质说明文案。

## 固定原则

- 所有产品与组织相关展示统一使用“开源乓协”。
- 本软件为独立开发项目，不代表学校或相关学生组织。
- V1 客户端目标：微信小程序 + Android App。
- V1 比赛项目只实现单打。
- 比赛性质：日常、考试、积分。
- 只有积分赛中双方均为有效正式成员的场次才可影响积分。
- 所有新正式成员初始积分为 1400。
- 第一版不开发在线支付、即时聊天、双打、团体赛、微服务。
- 比赛、积分、权限、审核均以后端规则为准，前端不得作为唯一安全边界。

## Codex 使用建议

让 Codex 每次只实现 `IMPLEMENTATION_SPEC.md` 中的一个 Phase。

每一阶段完成后必须：
- 运行自动化测试；
- 执行必要构建；
- 列出数据库变更和 API 变更；
- 对照 Gate 给出 PASS/FAIL；
- Gate 未通过不得进入下一阶段。
